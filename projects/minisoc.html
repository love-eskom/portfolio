MINISOC / DETECTION ENGINEERING

MiniSOC —
Stateful Detection Engine.

A modular Python security-monitoring project exploring how raw authentication logs can be transformed into normalized events, processed through reusable components and used as the foundation for detection and alerting.

01 / PROJECT CONTEXT

From raw logs to structured security events

Security logs are produced in source-specific formats. Building detection logic directly around every raw format can make a monitoring system difficult to extend and maintain.

MiniSOC explores a more structured approach: parse source data into a common event representation, then build further processing and detection capabilities around that normalized model.

The project is being developed incrementally, with an emphasis on clear component boundaries, predictable behaviour and tests that verify each part of the system.

02 / SYSTEM DESIGN

A modular processing pipeline

The intended architecture separates source-specific parsing from the shared event model and the components that will consume those events.

03 / IMPLEMENTATION

Core components implemented

The initial development work establishes the data structures and parser foundation needed for a maintainable detection system.

  • EventSchema: a normalized event model with fields including timestamp, source IP, user and event type.
  • Alert: a structured alert model that associates events with evidence and alert information.
  • BaseParser: an abstract base class defining a common interface for parser implementations.
  • LinuxAuthParser: parses Linux authentication log entries for accepted and failed SSH authentication, extracting relevant fields such as source IP, user, event type and timestamp.
  • Parser behaviour: non-matching log lines are discarded rather than being stored as parsed events.
  • Automated tests: pytest coverage has been added for the event model, alert model and parser behaviour.
04 / ENGINEERING DECISIONS

Why normalize events?

A parser should understand the format of its input source; detection logic should work with consistent event data. Keeping those responsibilities separate reduces the need for detection components to know the details of every log format.

The shared EventSchema provides a predictable contract between parsing and later processing. The BaseParser abstraction gives future parsers a common interface, while independent tests help verify that each component behaves as expected.

This is also the focus of the project's technical writing: documenting the reasoning behind the normalized event model, its fields and the interfaces around it.

05 / VALIDATION

Testing component behaviour

Testing is being used to validate the system's foundations as they are introduced. Current tests cover event construction, alert behaviour and Linux authentication parsing, including expected extraction and handling of non-matching records.

07 / ENGINEERING REFLECTION

Designing the system, not just the rules

MiniSOC is an exercise in combining software engineering with defensive security. The work involves more than writing detection conditions: it requires thinking about input formats, data contracts, component boundaries, error handling and testability.

As the project grows, the goal is to keep each part understandable and independently verifiable while developing a practical foundation for security-event analysis.
